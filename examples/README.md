# 预约泊位分配方法演示

这个小例子演示名义可行的预约安排，在到离场时间随机变化后怎样发生冲突，以及增加缓冲会怎样影响接纳和风险。

**范围**：本程序为 2026 年整理作品集时新增的教学示例。输入全部为合成数据，不是博士论文原始程序，不复现 98.2%、7.6% 或 0.43% 等论文指标。

## 运行

Python 3.10 或以上版本，无第三方依赖。在仓库根目录执行：

```bash
python examples/parking_allocation_demo.py
python examples/parking_allocation_demo.py --trials 1000 --seed 20261019 --output examples/demo_results.json --chart assets/demo-results.svg
python -m unittest discover -s examples/tests -v
```

## 实验设计

- 8 个请求、2 个泊位，时间单位为分钟。每个请求有名义起止时间、接纳权重和缓冲长度。
- 两种策略使用**相同的目标函数**，通过精确枚举求最大接纳权重。名义策略使用原时段；缓冲策略在两端增加请求自带的 guard。
- 到达时间偏差服从 `Uniform(-7, 3)`，离场时间偏差服从 `Uniform(-3, 12)`，均为人为指定的示例分布。
- 每轮对两种策略使用相同的一组随机到离场时间，即共同随机数，避免把两批随机样本的差别误认作策略效果。
- 同一泊位上实际占用区间相交视为冲突，半开区间端点相接不计冲突。一个请求与多个请求重叠时只计一次。
- 请求冲突率的分母为 `已接纳请求数 × 仿真轮数`。没有请求被接纳时返回 `null`，不报告具有误导性的零冲突率。

## 如何理解结果

必须同时看接纳数量、接纳权重与冲突率。少接纳请求也可能降低冲突，因此不能仅凭冲突率较低，就宣称某策略在所有指标上占优。

结果由代码生成并保存在 [demo_results.json](demo_results.json)。固定种子只能帮助复现，不能代替不确定性分析或现场验证。

## 与原研究的区别

原研究包含群体差异、解析冲突概率、多目标混合整数规划与动态缓冲。本例仅保留小规模加权接纳与固定 guard，用精确枚举实现，**没有**机会约束、多目标求解器、元启发式算法或在线动态缓冲。

枚举复杂度不适合大规模实例；示例分布也没有从真实停车数据标定。代码按这些限制解读和复用。

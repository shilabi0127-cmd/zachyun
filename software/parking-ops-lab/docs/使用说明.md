# 预约泊位决策台使用说明

先运行项目的 start.bat，再打开 http://127.0.0.1:8000 。这台电脑另有桌面入口“打开泊位决策台”，使用已安装的环境和 8770 端口。

## 先看示例

1. 保持 48 条示例订单和 4 个泊位，点击“计算分配与对比”。
2. 看五张策略卡片，同时比较接纳、费用和冲突，不要只选冲突最低的方案。
3. 在“泊位排程”切换策略，下方订单决定、风险组合和间隔建议会同步改变。
4. 展开页面底部规模实验，可以查看订单增加后的实际耗时及求解间隙。

## 使用自己的订单

下载 CSV 示例，用 Excel 编辑后保存为 UTF-8 CSV。每行一条预约，id 不重复，start/end 可填写 08:00 这样的时刻。fee 是预约费用，priority 是分配权重。

arrival_mean 为负表示平均早到，departure_mean 为正表示平均晚离；两个 std 是标准差，单位均为分钟。选择正态或均匀分布后，同一组均值与标准差会产生不同尾部风险。只有点击“应用到全部已载入订单”，界面里的统一参数才会覆盖每条订单的 CSV 参数。

failure_tolerance 为单条预约允许的冲突概率，0.05 表示 5%。留空时采用默认 α 除以权重平方根。booking_order 是下单先后序号，先到先得按它排序；全部留空时使用 CSV 行序。

## 理解输出

接纳决定和泊位号给出可以采用的分配表。前后缓冲列适用于扩窗方法；风险约束方法通过选择相容的订单组合控制风险，不会自动挪动预约时间。

同泊位风险表给出最值得检查的预约组合。间隔建议用于查看前单晚离与后单早到时需要多少空间，“尚缺”大于零并不等于系统已经修改了时间。

预约费用不是净利润。未接纳不意味着这条单独无法服务，只表示当前策略没有选它。求解间隙不为零或“未返回”时，不能把结果叫作已证明最优。

## 保存

完整 JSON 包括订单、配置、种子、分配与指标。分配表、风险组合和间隔建议也可以分别导出 CSV。网页刷新或服务重启后，内存记录可能消失，重要结果应先导出。

命令行复现已保存记录

```bash
python -m parkinglab --replay parking-experiment.json --output results/replayed
```

所有示例和规模实验均为合成订单。当前版本是可运行的决策原型，不是博士论文算法的完整复现，也没有验证真实停车场上线效果。
